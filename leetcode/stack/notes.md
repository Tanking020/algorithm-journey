# 栈 · 章节笔记

> 对应题目：20 有效的括号 · 155 最小栈 · 739 每日温度 · 84 柱状图中最大的矩形
>
> 更新时间：2026-09-30

## 一、核心思想：栈的三种角色

栈本身只是"后进先出"的容器，难点在于**明确它在本题里扮演什么角色**。

| 角色 | 题目 | 关键动作 | 一句话 |
|---|---|---|---|
| **① 配对 / 抵消** | **20** 有效的括号 | 相邻匹配就弹出 | 把能消掉的消掉，剩下的就是答案 |
| **② 辅助记录** | **155** 最小栈 | 与主栈**同步**升降，记录历史信息 | 只记一个全局最小值无法"回退" |
| **③ 单调淘汰** | **739 / 84** | 新元素淘汰"永远再用不到"的旧元素 | 单调性是**弹出来的**，不是排出来的 |

> 从"抵消" → "记录" → "淘汰"，恰好是栈从入门到进阶的完整光谱。

## 二、识别信号

| 看到题面出现 | 该想到 |
|---|---|
| "括号、标签、嵌套、配对" | **普通栈（抵消）** |
| "撤销最近操作"、"回退到上一个状态" | 栈（也是迭代式 DFS 的基础） |
| "后缀表达式求值"、"中缀转后缀" | 栈 |
| 需要在 $O(1)$ 内查询**历史极值** | **辅助栈**（155） |
| **"下一个更大/更小"、"还要等几天"、"左右第一个比我高/矮"** | **单调栈**（739/84） |
| "柱状图最大矩形"、"接雨水"、"每个元素作为最值能延伸多远" | **单调栈** |
| "**滑动窗口内**的最大值/最小值" | ⚠️ **单调队列**（`deque`，如 239），**不是栈** |

> **最实用的判据**：**题目要你找"最近的、比我大（或小）的元素" → 单调栈，不用犹豫。**

## 三、单调栈：三个必问的问题

```python
stack = []
for i, x in enumerate(arr):
    while stack and (新元素 x 破坏了栈顶的单调性):
        j = stack.pop()
        # ★ 在这里结算 j：此时 i 就是 j 的"下一个更大/更小"
    stack.append(i)
# 循环结束后栈里剩下的下标 = "右边没有答案"的那些
```

| 问题 | 739 | 84 |
|---|---|---|
| ① 栈里存**值**还是**下标**？ | **下标**（要算距离） | **下标**（要算宽度） |
| ② 栈内**递增**还是**递减**？ | 求"更高" → **非递增** | 求"更矮" → **非递减** |
| ③ 什么时候**结算**？ | `t > heights[栈顶]` | `heights[栈顶] > h` |

**方向口诀**：**求"下一个更大" → 递减栈；求"下一个更小/更矮" → 递增栈。**

**为什么维护单调性有用**：单调性保证"栈顶一定是**最容易被新元素淘汰**的那个"，于是"该弹的能立刻弹、该留的稳稳留" —— 这就是 $O(n)$ 的来源。

## 四、两个哨兵技巧

| 技巧 | 用途 | 例子 |
|---|---|---|
| **末尾补 0 / 补最小值** | 让"右边没有更矮元素"的柱子也能被结算，省掉循环外的收尾代码 | 84：`heights = heights + [0]` |
| **左边界取 `-1`** | 栈空时表示"一路向左都没遇到更矮的" | 84：`left = stack[-1] if stack else -1` |

> ⚠️ **不要用 `stack.clear()` 收尾** —— 循环结束时栈里剩下的元素**正是答案的一部分**（还没结算），清空会丢信息。

## 五、我踩过的坑（重点回顾）

### 🔴 坑 1：变量定义了不在 while 里更新 → 死循环 / IndexError（犯了三次！）

| 题目 | 错误写法 | 后果 |
|---|---|---|
| **567** | `window_length` 算一次就当 while 条件 | 死循环 |
| **20** | `b1/b2/b3` 算一次就当 while 条件 | `pop from empty list` |
| **20** | 改用内联表达式后仍漏了长度保护 | `IndexError` |

```python
# ❌ b1/b2/b3 是"快照"，循环里 st 变了它们不变
while b1 or b2 or b3:
    st.pop()
```

**教训**：`while` 条件里出现的所有变量，**循环体必须能推进它们**；能内联就内联。

### 🔴 坑 2：运算符优先级（20 题）

`not` > `and` > **`or`**，所以：

```python
# ❌ 实际等价于 (len>=2 and 第一组) or 第二组 or 第三组
#    → 长度保护只罩住第一个分支，栈短时 st[-1]/st[-2] 直接 IndexError
while len(st) >= 2 and (st[-1]=='}' and st[-2]=='{') or (st[-1]==']' and st[-2]=='[') or ...:

# ✅ 用括号把整个"或"表达式包起来
while len(st) >= 2 and (
        (st[-1] == '}' and st[-2] == '{')
        or (st[-1] == ']' and st[-2] == '[')
        or (st[-1] == ')' and st[-2] == '(')):
```

> **"and + 或列表"混用时，一定要给'或'加括号"** —— 这是个反复出现的坑。

### 🟡 坑 3：`.pop()` 放在条件里会**真的删除元素**

```python
if not st or st.pop() != pairs[ch]:    # 空栈时 or 短路 → pop() 不执行 ✅
    return False
```

- 方法是**调用**，只要被求值就有副作用（删除 + 返回被删元素）；
- 靠 `or` 的**短路**保护：`not st` 为真时右边不执行；
- 一句提醒：**在条件里写有副作用的调用要格外小心**，把 `or` 写成 `and` 就会静默出错。

### 🟡 坑 4：空栈能 `.clear()`，但不能 `.pop()`

| 操作 | 空列表上 |
|---|---|
| `a.clear()` / `del a[:]` | ✅ 安全（清空空的 = 没变化） |
| `a.pop()` / `a.remove(x)` / `a[-1]` | ❌ 报错 |

另注意 `a.clear()` 是**原地**清空（其他引用也会看到空），`a = []` 只是**重新绑定名字**。

### 🟡 坑 5：155 为什么必须"每层都记"最小值

只存一个全局最小值，`pop` 掉它之后就**不知道之前的最小值了** → 无法"回退"。
辅助栈与主栈**等长同步升降**，才能让最小值自动回退。

### 🟡 坑 6：84 的**左 ≤ 右 <** —— 不对称！

| 边界 | 判定 | 严格？ | 准确性 |
|---|---|---|---|
| 右边界 | `heights[栈顶] > h` | **严格** `<` | ✅ `i` 一定是"右边第一个严格更矮" |
| 左边界 | 弹出后的新栈顶 | **不严格**（可等高） | ⚠️ 有时不是"最靠右的严格更矮" |

**等高时单根柱子算出的宽度会偏小，但同一串等高的柱子中【最左那根】会拿到完整宽度 → 全局最大值仍正确。**

> 所以栈是"**非递减**"而不是"严格递增" —— 用词要准确。

## 六、面向对象：155 教会我的类写法

**Core**：`self.xxx` 才是"存进对象"的状态，方法间才能共享。

| 要点 | 说明 |
|---|---|
| `self` 是什么 | 当前那个对象；调用时不用传（`s.push(3)` → `MinStack.push(s, 3)`） |
| 属性名是"标签"不是"盒子" | `self.a = []` 和 `self.b = {}` 是**两个独立对象**，改一个不影响另一个 |
| 别名陷阱 | `self.b = self.a` 才是**同一个对象**；用 `a is b` / `id()` 检测 |
| 漏写 `self.` | 只是**局部变量**，方法结束即销毁（`AttributeError` / `NameError`） |
| 引用独立 ≠ 逻辑同步 | 155 里两个列表互相独立，但"长度必须一致"是**你的代码**要负责维护的 |
| 接口 vs 内部 | `M.pop()` ✅ 走接口；`M.stack.pop()` ❌ 绕过接口 → 静默破坏同步，`getMin` 出错 |

**类的骨架**：
```python
class MinStack(object):
    def __init__(self):        # 构造：对象创建时自动执行一次
        self.stack = []        # 实例属性
    def push(self, val):       # 实例方法：第一个参数必须是 self
        self.stack.append(val)
```

## 七、元组（155 方法 A 用到）

| 要点 | 说明 |
|---|---|
| 访问 | `self.stack[-1][1]`：先取列表末元素（元组），再取元组第 1 位 |
| 解包 | `val, cur_min = self.stack[-1]`（可读性更好） |
| 不可变 | `t[0] = x` ❌；但 `stack[i] = (a, b)` ✅（替换列表里的元素） |
| 单元素元组 | 必须写 `(5,)`，`(5)` 是 int |
| **为什么不用 dict** | 字段固定且只有 2 个 → 元组最轻量；dict 要重复存键名，内存和速度都更差 |

**两种解法实测对比**（n = 5 万）：

| | 方法 A（单栈 + 元组） | 方法 B（双栈） |
|---|---|---|
| 空间实测 | ≈ 5.04 MB | ≈ **2.29 MB**（省 2.2×） |
| 原因 | 每个元组约 **56 字节**对象开销 | 辅助栈只存**已有 int 的引用** |
| 代码观感 | `top()` 要写 `[-1][0]`，略绕 | `top()` 直接 `[-1]`，直观 |

> 反直觉结论：**CPython 里"看起来更省的元组方案"反而更费内存。**

## 八、均摊分析（739/84 是 O(n) 的真正原因）

> **每个下标最多入栈一次、出栈一次** → 总操作数 ≤ 2n → 均摊 $O(1)$ / 元素。

⚠️ **不是靠"剪枝 / 跳过"省下来的**。我曾想过"确定一个矩形后跳过其区间内元素"，这是**错的**：

```
heights = [1, 100, 1]
i=0 的矩形跨度是整个数组，面积只有 3
但 i=1 在它区间内，面积是 100    ← 跳过就漏掉了！
```

**原因**：区间内可能有**更高**的柱子，宽度虽窄但高度大得多，面积反而更大 → **每根柱子都必须单独考虑。**

## 九、易混辨析：11 盛水 vs 84 最大矩形

| | 11 盛最多水的容器 | 84 柱状图中最大的矩形 |
|---|---|---|
| 形状 | 两壁之间**空**的容器 | **实心**矩形 |
| 高度由谁定 | 左右两壁中**较矮**的那根 | 区间内**最矮**的那根 |
| 中间元素 | **完全不参与** | **全部参与** |
| 算法 | **双指针** | **单调栈** |

**判据（一句话）**：
> **"中间的元素参不参与？"** 不参与 → 双指针；参与（最矮的说了算）→ 单调栈。
> 再问一句：**"我是选两个位置，还是为每个位置找边界？"** 后者 → 单调栈。

**同一数组两题答案不同**（说明它们真的不是一类）：

| 数组 | 11 | 84 |
|---|---|---|
| `[2,1,2]` | 4 | 3 |
| `[1,2,1]` | 2 | 3 |
| `[1,2,3]` | 2 | 4 |
| `[1,100,1]` | 2 | **100** |

## 十、复杂度速查

| 题 | 时间 | 空间 | 要点 |
|---|---|---|---|
| 20 有效的括号 | $O(n)$ | $O(n)$ | 映射表 + 抵消；遇到不匹配可**提前 return** |

## 十一、面试可以这么说

> "栈类问题先分清**角色**：20 是配对抵消，155 是辅助记录历史信息，739/84 是单调淘汰。
> 单调栈我习惯先问三个问题：**栈里存值还是下标**（要算距离/宽度就存下标）、**单调方向**（找更大的用递减栈，找更小的用递增栈）、**什么时候结算**（新元素破坏单调性时）。
> 复杂度 $O(n)$ 来自**均摊**：每个下标最多入栈出栈各一次。"
>
> "84 有个细节值得说：它的**左边界是 ≤ 而右边界是 <**，不对称。这是因为我用的是严格 `<` 弹栈，等高不会互相阻挡 —— 单根柱子算出的宽度可能偏小，但同一串等高的最左那根会拿到完整宽度，所以全局最大值仍然正确。"
